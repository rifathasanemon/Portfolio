Aug–Sep 2026Client delivery

Per-file data loads for a banking client

I built the ingest path for a bank's enterprise data migration, which covers fetching each file, loading it, validating it, archiving it and releasing it.

  • Read the blind-load and validator feeds straight from SFTP, with connector credentials supplied from the environment.
  • Translated the client's validator JSON into the platform's VALIDATE rules, and made REFERENTIAL rules check against their reference tables.
  • Added a LoadCycle workflow step so each load cycle cleanly replaces the previous one.
  • Provisioned all four feeds to the SIT environment, one workflow per file, archived under a dedicated path.
  • Fixed parsing of text-month dates and corrected the client's declared date format.

Sep 2026Performance

Load performance guardrails

A transaction feed of 25 files was loading at 42 rows per second and getting slower. I traced it to two platform defects, wrote the spec, and fixed both.

  • Found that keyed upserts scanned the whole table when the key had no index, so the rate fell as the table grew. The platform now warns when this happens.
  • Moved filter logging off the per-row hot path, so it reports once per run.
  • Fixed a ForEach step that started once per dispatch pass instead of once.
